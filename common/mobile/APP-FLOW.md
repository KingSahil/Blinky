# Blinky Mobile (Expo) — Application Flow

> Companion remote-control app for the Blinky desktop agent.
> This document explains ONLY the mobile app (`common/mobile/`): its startup,
> connection, messaging, voice, quick-action, and screenshot-viewer flows.

---

## 1. Files & roles

| File | Role |
|---|---|
| `index.ts` | Expo entry — `registerRootComponent(App)` |
| `App.tsx` | The entire UI + app state + flows (single file, ~2000 lines) |
| `usePCWebSocket.ts` | WebSocket transport: connect/disconnect, auth, send frames |
| `app.json` | Expo config (orientation, icons, android package) |
| `eas.json` | EAS build profiles (development/preview/production) |
| `assets/` | Icons + splash |
| `bun.lock` | Canonical lockfile (npm `package-lock.json` is gitignored) |

**Stack:** Expo SDK 54 · React Native 0.81 · React 19 · TypeScript strict.
Key libraries: `expo-audio` (recording), `expo-haptics`, `expo-linear-gradient`,
`expo-network`, `@react-native-async-storage/async-storage`,
`react-native-gesture-handler`, `react-native-volume-manager` (optional).

## 3. Startup flow

```
App mounts
  │
  ├─► loadIp()  [useEffect on mount]
  │     ├─ Promise.all( AsyncStorage '@blinky_pc_ip', '@blinky_pc_token' )
  │     ├─ detectedIp = Constants.expoConfig.hostUri (Expo dev host, if any)
  │     ├─ initialIp = savedIp || detectedIp || 'localhost'
  │     ├─ savedToken → setRemoteToken()
  │     └─ connect(initialIp, savedToken?)          → AUTOMATIC connect
  │
  ├─► render: header (status dot) + welcome bubble + chat bar
  │
  └─► if status === disconnected|error after ~2.5s
        └─► handleAutoDiscoverQuietly()  (silent subnet scan, see §5)
```

**State machine (connection):**

```
 disconnected ──connect()──► connecting ──onopen + auth──► connected
      ▲                           │                           │
      │                           │ onerror                    │ onclose
      │                           ▼                           ▼
      └────────────────────── error ─────────────────────────┘
```

## 4. Connection & auth flow (`usePCWebSocket.ts`)

```
connect(ip, token?)
  ├─ disconnect() any existing socket
  ├─ trim ip; append ":9001" if no port → ws://<ip>:9001
  ├─ status = 'connecting'
  ├─ new WebSocket(wsUrl)
  │
  ├─ onopen:
  │    ├─ if token: send(`auth:${token}`)     ← FIRST frame, before anything
  │    └─ status = 'connected'
  │
  ├─ onmessage:
  │    ├─ try JSON.parse → setLatestResponse(parsed)
  │    └─ catch → log raw message (non-JSON frames, e.g. logs)
  │
  ├─ onclose  → status 'disconnected', clear socket
  ├─ onerror  → status 'error'  ("Check IP and firewall.")
  └─ onunmount → close socket
```

**Why the auth frame matters:** the desktop gateway (`websocket.rs`) trusts
loopback peers but requires `BLINKY_REMOTE_TOKEN` (constant-time compare) for
all non-loopback connections. The phone always presents `auth:<token>` on open
so the LAN connection is authorized before any command is accepted. Tokens are
generated by the desktop into `.env` and copied manually into the app's
"Remote token" field.

**Sending:**

| Purpose | Frame | Payload |
|---|---|---|
| Quick command | raw string | `power_off` `restart` `sleep` `volume_up` `volume_down` `volume_mute` `lock` |
| Chat / agent query | JSON string | `{ "requestId": "<uuid>", "query": "<text>" }` |
| STT key request | raw string | `get_sarvam_key` |

## 5. Subnet discovery flow

Two entry points use the same scanner:

```
scanSubnet(subnet)                  // e.g. "192.168.1"
  ├─ build 254 IPs  (.1 .. .254), port 9001, timeout 600ms
  ├─ scan in batches of 35 (concurrency)
  │    ├─ batch: Promise.all(checkIpAddress × 35)
  │    └─ first success → return that IP (stops scanning)
  └─ null if nothing answered

checkIpAddress(ip):
  ├─ open ws://ip:9001
  ├─ onopen  → close probe socket, resolve(ip)
  ├─ onerror → reject
  └─ timeout 600ms → reject
```

**Invoked from:**

1. **Quiet auto-discovery** (startup, if disconnected after 2.5s):
   phone gets its own IP via `expo-network`, derives the /24, scans silently,
   connects on first hit. No UI shown.
2. **Manual "Scan Subnet"** (Local Link Setup):
   shows progress text ("Searching subnet (checking IPs X to Y)...") + spinner,
   connects on hit, or `Alert "Blinky Not Found"` if empty.

## 6. Chat query flow (the core loop)

```
user taps Send / presses enter (queryText non-empty)
  │
  ├─ triggerHaptic('light')
  ├─ setRunningQuery(query)
  ├─ setAgentStatus('processing'); timerSeconds=0
  ├─ create userMsgId + blinkyMsgId (uuid)
  ├─ activeBlinkyMsgIdRef.current = blinkyMsgId
  ├─ messages += [ user bubble, "I'm on it. Locating..." bubble w/ progress{0%, 'Analyzing query...'} ]
  ├─ sendQuery(query, uuid)  → WS JSON frame
  └─ if send fails → mark that bubble "Failed to communicate with PC."

WHILE processing (1s interval):
  ├─ progress crawls: percent = min(94, current+1); duration++
  └─ mapped by keywords: analyzing/speech=15%, screenshot/capturing=50%,
     opening/triggering=60%, playwright=55%, else min(94, 15+8×sec)

DESKTOP STREAMS BACK → latestResponse effect:
  ├─ status='processing' (is_chunk): statusText += chunk  (streamed answer)
  ├─ status='processing' (message):  statusText = message
  │     percent = data.percent | data.confidence | keyword map
  ├─ status='success':
  │     ├─ active bubble → 100% / "Action completed."
  │     ├─ activeBlinkyMsgIdRef = null
  │     └─ append final bubble { text: data.response,
  │                              screenshot_b64?, steps[]? }
  └─ status='error':
        ├─ active bubble → % frozen, statusText = error.message
        └─ append error bubble

Autoscroll: every messages change → scrollToEnd (100ms delay).
```

**Success bubble extras:**

- `screenshot_b64` → rendered as a thumbnail with "Tap to enlarge" badge → opens
  the full-screen PinchableImageViewer (§8).
- `steps[]` → numbered step trace: each step renders a badge (`step.step||index+1`)
  + instruction text + optional `target_text` chip. Mirrors the desktop overlay's
  guidance steps.

**Stop button** (visible while processing):
- heavy haptic, `agentStatus='idle'`, runningQuery cleared
- active bubble → "Stopped by user."
- ⚠️ **UI-only stop**: no "cancel" frame is sent to the desktop; the daemon
  keeps executing in the background.

## 7. Voice command flow (Sarvam STT)

```
mic button tapped
  │
  ├─ not connected        → Alert 'Not Connected'
  ├─ no sarvamApiKey      → Alert 'Configuration Missing' + sendCommand('get_sarvam_key')
  │                         (key requested from desktop on every connect:
  │                          latestResponse.type === 'sarvam_key' → setSarvamApiKey)
  │
  ├─ requestRecordingPermissionsAsync → if denied: Alert, exit
  ├─ setAudioModeAsync({ allowsRecording: true, playsInSilentMode: true })
  ├─ audioRecorder.prepareToRecordAsync() + record()
  ├─ heavy haptic; isVoiceRecording = true (mic turns red)

mic button tapped again (stop)
  ├─ medium haptic; isVoiceTranscribing = true (spinner in mic slot)
  ├─ audioRecorder.stop() → uri
  ├─ FormData:
  │     file    = { uri, type: 'audio/x-m4a' (android) | 'audio/wav' (ios),
  │                name: 'query.m4a' | 'query.wav' }
  │     model  = 'saaras:v3'
  │     language_code = 'en-IN'
  ├─ POST api.sarvam.ai/speech-to-text, header 'api-subscription-key'
  ├─ transcript = data.transcript.trim()
  │
  ├─ transcript non-empty:
  │     ├─ setQueryText(transcript)
  │     └─ same chat-query flow as §6 but progress starts 'Analyzing speech...'
  └─ empty → Alert 'Could not hear anything clearly.'
  └─ finally: isVoiceTranscribing = false
```

## 8. Screenshot viewer flow (pinch / pan / double-tap)

```
tap screenshot thumbnail in a success bubble
  ├─ light haptic
  └─ setPreviewImageUri(`data:image/jpeg;base64,${b64}`)

Modal opens → PinchableImageViewer(uri)
  ├─ Close button (top-right) → onClose()
  ├─ Reset button (top-left)   → spring back to scale=1, x=0, y=0

Gesture composition (simultaneousHandlers wired three ways):
  ├─ TapGestureHandler (2 taps)  → toggle 1x ↔ 2.5x (focal-anchored)
  ├─ PinchGestureHandler         → scale 0.6x..6x
  │     ├─ BEGAN: pinchStartScale = current; selection haptic
  │     └─ END:   clamp 1..5; bounce; clamp translations to bounds
  └─ PanGestureHandler (1 pointer)
        ├─ ignored while scale ≤ 1.05 (returns to 0,0 on release)
        ├─ while zoomed: bounded pan + rubber-band past edges (0.3 factor)
        └─ END: clamp to bounds, spring back

State handling: Animated.Value + value listeners keep scaleVal/txVal/tyVal
in refs so every handler reads the CURRENT transform (no stale closures).
```

## 9. Quick actions & power commands

```
⋮ menu (header)
  ├─ Local Link Setup          → toggles connection card (§5 manual panel)
  ├─ Mute Volume               → triggerQuickAction('volume_mute')  [no confirm]
  ├─ Capture Screenshot        → handleCaptureScreenshot()
  │     └─ query = 'Capture screenshot of current PC screen' → §6 flow
  ├─ Lock Workstation          → sendCommand('lock')             [no confirm]
  ├─ Sleep Mode                │
  ├─ Reboot PC                 ├─ triggerPowerCommand(...)  → Alert confirm
  └─ Shutdown PC               │     (Cancel | Confirm, destructive style)
                                └─ on Confirm: sendCommand; feedback banner 3s
```

All quick actions: medium/heavy haptic, menu closes, green "Command sent!"
banner for 3s, or `Alert 'Failed to send command. Check link.'` if the socket
is not open.

## 10. Hardware volume key hijack

```
connected AND VolumeManager available:
  ├─ showNativeVolumeUI({enabled: false})     // suppress system volume UI
  ├─ getVolume() → lastVolume baseline
  ├─ addVolumeListener:
  │     ├─ currentVolume > lastVolume → sendCommand('volume_up')
  │     ├─ currentVolume < lastVolume → sendCommand('volume_down')
  │     ├─ clamp 5%..95% (setVolume + lastVolume bookkeeping)
  │     └─ lastVolume = currentVolume
  └─ cleanup on disconnect/unmount:
        volumeListener.remove(); showNativeVolumeUI({enabled: true})

Effect: the phone's physical volume keys become the PC's volume keys
while Blinky is linked.
```

## 11. Persistence (AsyncStorage)

| Key | Value | Written |
|---|---|---|
| `@blinky_pc_ip` | IP/hostname | handleConnect, both discoveries |
| `@blinky_pc_token` | remote token | handleConnect only |

- Loaded together at startup, auto-connect attempted immediately.
- ⚠️ `handleConnect` writes the token field **unconditionally** — clearing the
  token input then connecting overwrites the stored token with an empty value.

## 13. Known quirks / improvement candidates

1. **Stop is UI-only** — no cancel frame reaches the daemon (§6).
2. **requestId is never correlated** — responses attach to the ref-tracked
   active message; concurrent queries would mis-attach (§6).
3. **Token overwritten when field cleared** (§11).
4. Mic button shows `mic` icon in both idle and recording states (color only)
   (§7).
5. `keyboardType="numeric"` on the IP field hampers hostname entry (§5).
6. No reconnection backoff — a dropped link needs manual reconnect or a full
   app restart to re-trigger auto-discovery (§5).
7. Single-file monolith (`App.tsx` ~2000 lines) — the top refactor candidate.
