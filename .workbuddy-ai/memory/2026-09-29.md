# 2026-09-29

## Fixed: Expo Android bundling was broken by a bad merge (mobile app)

Symptom: `expo start` → `SyntaxError: App.tsx: Expected corresponding JSX closing tag for <Modal>
(2454:10)`.

Root cause: **merge `f8146b6` ("Merge branch 'main' into assembly_ai") resolved `common/mobile`
to the assembly_ai side and silently dropped main's work.** Three files regressed:

- `common/mobile/App.tsx` — lost `activeTab`, `showSplash`, `isLightOn`, the PIN/Unlock modal
  state + body, the Files-screen wiring, `useFonts`, and attached-file support. The PIN `<Modal>`
  was left unclosed and its body had been overwritten with a copy of the chat `messages.map`
  block, followed by a duplicate slash-command menu and a duplicate bottom chat bar.
- `common/mobile/usePCWebSocket.ts` — lost the whole filesystem API
  (`QuickAccessFolder`, `FsEntry`, `FsDirContents`, `FsFileData`, `quickAccessFolders`,
  `listDirectory`, …) and `LightEvent` (−233 lines).
- `common/mobile/package.json` — lost 10 deps (`expo-font`, `expo-file-system`,
  `expo-image-picker`, `expo-intent-launcher`, `@expo/ui`, `@expo/metro-runtime`, `@expo/ngrok`,
  `@react-native-masked-view/masked-view`, `react-dom`, `react-native-web`).

Note: the JSX error was the *second* error. Someone had already changed `let query = …` →
`query = …` at line 1180 to clear `Identifier 'query' has already been declared`, which unmasked
the Modal error. Two errors, first masking the second.

  `tmp/usePCWebSocket_broken_20260929.tsx`.

### Test suite: `bun test` in `common/mobile` — 23 pass / 0 fail

One test needed attention, and the reasoning matters:

`tests/usePCWebSocket.test.ts` → "restoring credentials reconnects after a failed token attempt"
asserted `timers.size === 0` after a successful reconnect. It **fails** with main's
`usePCWebSocket.ts`. This is **not** a regression I introduced — proof: the hook in the tree is
`6bd6b00`'s blob plus exactly one line, and `common/mobile/tests/` is byte-identical to `6bd6b00`,
so the suite was already red at `6bd6b00`. The merge had "fixed" it only by deleting the Files
feature.

Cause: main's native (release) path schedules a deferred `setTimeout(…, 300)` after successful
auth to request `get_system_info` + `fs_get_quick_access` + `fs_get_recent`. The assembly_ai
version had no such timer (it never requested initial telemetry on the native path at all), so
the old `timers.size === 0` assertion encoded the *buggier* behaviour.

Fix: replaced the bare timer count with a behavioural assertion — drain every pending timer and
assert the connection is still `connected`, `errorMsg` still null, and `close` was never called
with the live socket id. Strictly stronger than the old assertion (it still catches a leaked
connect timeout, which is what the test was actually for) and no longer couples to a side-effect
count.

### Method that worked (reusable)
1. `git log --oneline -- <path>` to find candidate revisions, then `git show <rev>:<path>` to
   extract each and `wc -l` them — a merge result that is *shorter* than one parent usually lost
   content.
2. Parse each candidate with `tmp/jsxcheck.js` to find the last syntactically valid one. Babel
   only catches syntax, so pair it with `tsc --noEmit` to catch the undefined identifiers that a
   bad merge leaves behind (that second class of error is invisible to the bundler until runtime).
3. `git diff <good-rev> -- <dir>` to find *every* file the merge regressed, not just the one that
   fails to compile.
