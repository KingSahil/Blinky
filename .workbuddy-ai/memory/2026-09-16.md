### The commit could not be made at all — three separate faults

1. **`git commit` failed with `fatal: unable to read tree (4e8e29fa)`, exit 128.** The parent
   commit's tree is incomplete, and git needs it. `-q` does not help.
2. **`git write-tree` failed with `invalid object 100644 0360431f for
   common/frontend/src/lib/types.ts`.** The *index* referenced 19 blobs that no longer exist.
3. **`git add` silently failed to fix them** — exit 0, nothing repaired, because it trusts the
   stat cache and skipped re-hashing.

Diagnosis scripts left in `tmp/` (gitignored): `check_index.py` scans every index entry for a
missing blob; `walk_head.py` walks HEAD's tree and reports missing trees and blobs.

Fixes, in order: `touch` the 19 files to invalidate the stat cache, `git add` them (index now
intact, 0 missing), then build the commit directly since `git commit` is unusable:

```
TREE=$(git write-tree)
COMMIT=$(git commit-tree "$TREE" -p HEAD -F tmp/commit-msg.txt)
git update-ref refs/heads/main "$COMMIT"
```

Result: `62b585b8` on `main`, parent `d4ca36d`, tree `5348ddc9`.
**Its own tree is complete** (81 trees walked, 0 missing), so `git status` and `git diff HEAD`
work again. `git show HEAD` / `git log --stat` still fail (they diff against the broken parent),
and `git push` is at risk for the same reason — untested.

### ⚠️ My `touch` killed the running dev server

The `touch` I used to invalidate the stat cache bumped the mtime of files **Tauri watches**.
The dev log shows it plainly:

```
Info File common\src-tauri\src\websocket.rs changed. Rebuilding application...
Compiling blinky v0.1.0 ... Finished `dev` profile in 1m 27s
error: process didn't exit successfully: `target\debug\blinky.exe` (exit code: 1)
error: script "dev" exited with code 1
```

The rebuild restarted the app and the restarted process exited 1. The stderr file was **empty**,
so there is no panic to read. I had also touched `common/src-tauri/Cargo.lock` and
`scripts/dev.ts`. Restarted clean afterwards.

**Lesson: never `touch` files under a watched source tree while a dev server is running.**
Use the index-only repair instead (below), which leaves mtimes alone.

### Verified the correct repair in throwaway repos

Reproducing the failure needs more than deleting a blob: `git write-tree` reads the index's
cache-tree and does **not** validate blobs it isn't rewriting, so it still returns 0. Deleting
the blob *and* invalidating that directory's cache-tree (by adding a sibling file) reproduces
the real error exactly:

```
error: invalid object 100644 ce0136… for 'a.txt'
fatal: git-write-tree: error building trees   (exit 128)
```

Verified repair, **no worktree touch**:

```bash
sha=$(git hash-object -w --path=<path> <path>)
mode=$(git ls-files -s <path> | awk '{print $1}')
git update-index --cacheinfo "$mode,$sha,<path>"
```

The recomputed sha matched the original byte-for-byte, mtime was **unchanged**, and
`write-tree` returned 0. This is now the primary method in the skill; `touch` is the fallback
with a warning attached.
